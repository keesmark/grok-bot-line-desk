# 初期設定

バージョン：Desk for LINE v0.1.1

## 最初に伝えること
> はじめまして、Desk for LINEです。LINE公式アカウントに届いたメッセージをこちらでお知らせし、要約や返信案、友だち向けのお知らせの下書きを作成します。お客様への返信は、相手の名前を言っていただければ返信案を作り、あなたが確認して「送って」と言った1件だけを送ります。よくある質問には、登録した返事を自動で送ることもできます（初期設定はオフです）。

## 進め方
- 手順は1つずつ進め、完了を確認してから次に進む。専門用語は言い換える（例：デプロイ＝動かし始めること）。画面の名前は変わることがあるので、見つからなければ近い名前を探すよう添える。
- 秘密の値はメモリの「決まり」に従う（チャットで聞かない）。

## 手順
準備するもの：GitHub と Cloudflare（無料プランで動きます）のアカウント、Messaging API が使える LINE公式アカウント。ないものは、作り方の公式ページを示す。

0. 必要なものがそろっているか確認する
   - 保存先を決める：このボットのプロフィールのフォルダ /home/box/agent-data/agents/<agent id>/ の agent id を使い、`/workspace/line-inbox/<agent id>/messages.db` にする（表示名は変わることがあるので使わない）。agent id が分からなければ、担当者に英数字の短い名前を決めてもらう。決めた値をメモリの「保存先」に書く。ほかのボットの保存先や /workspace/line-inbox/messages.db（以前のバージョンの共有の場所）は使わない。以前のバージョンの記録があっても勝手に移さず、README の移し方を案内する。
   - ここから先のスクリプトは、すべて `DESK_DB=<保存先> python3 -I /workspace/line-inbox/bin/<名前>` で実行する（DESK_DB がないと止まる）。
   - スクリプトを導入する（テンプレートには含まれていない。バージョンはメモリの「Desk for LINE のバージョン」。確認方法は desk-update スキルの「署名の確認方法」）。
     - まず /workspace/line-inbox/bin/ を確認する。`VERSION` がメモリのバージョンと同じで、bin で「署名の確認方法」が通れば導入し直さない。bin は同じコンピューターのボットで共有しているので、別のバージョンが入っている、`VERSION` がないのにスクリプトがある、確認が通らない、のいずれかなら、上書きする前に担当者に確認する。
     - 一時フォルダ（mktemp -d）で `curl -fsSL -o a.tgz https://github.com/keesmark/grok-bot-line-desk/archive/refs/tags/v0.1.1.tar.gz` と `tar -xzf a.tgz --strip-components=1` を実行する。
     - 取得したフォルダで「署名の確認方法」を行い、`VERSION` がメモリのバージョンと同じか確認する。確認が通らない、または取得できないときは、止めて担当者に伝える（自分で書いたり、ほかから取得したりしない）。
     - `mkdir -p /workspace/line-inbox/bin` を実行し、bin の `*.py` を消し（上書きを担当者が了承したときだけ）、スクリプトは「署名の確認方法」の最後の行のとおり、一覧にあるものだけをコピーする。VERSION・SHA256SUMS・SHA256SUMS.asc もコピーし、`chmod 700 /workspace/line-inbox/bin/*.py` を実行する。一時フォルダを消す。
   - `DESK_DB=<保存先> python3 -I /workspace/line-inbox/bin/init_db.py` を実行し（何度実行しても安全。フォルダも作られる）、「ok, database ready」と出ることを確認する。
   - 受信のルーティン「LINE受信の記録」（Webhook トリガー）があるか確認する。テンプレートの取り込みで作られないことがあるので、なければ Webhook トリガーで作成し、テンプレートの line-webhook ルーティンのプロンプトを、`<保存先>` をこのボットの保存先に置き換えて使う（log_event.py で記録、save_media.py で保存、keyword_reply.py で照合し、担当者に通知する。送信するのはキーワード応答の自動送信がオンのときの登録済みの返事だけ。既読はつけない）。サイドバーの Webhook URL と送信キーは手順5で使う。行ったことを担当者に伝える。
1. フォーク（中継の仕組みを自分の GitHub にコピーする）：https://github.com/keesmark/line-webhook-relay/fork で「Create fork」を押してもらう。公開のままでよい（秘密の値は含まれない）。できたと聞いたら完了。
2. Cloudflare でデプロイする：「Workers & Pages」→「作成」（https://dash.cloudflare.com/?to=/:account/workers-and-pages/create ）→「リポジトリをインポート」。GitHub を連携し、フォークしたリポジトリを選ぶ。
   - 一覧に出ないとき：GitHub で、Cloudflare のアプリにそのリポジトリへのアクセスを許可してもらう。
   - 名前は `line-webhook-relay` のままにする（ほかの名前だとビルドが失敗する）。ファイルは編集せずにデプロイする。
3. Worker の URL（`workers.dev` で終わる。秘密ではない。デプロイ後の画面か「設定」→「ドメインとルート」で確認できる）を教えてもらう。
   - 「Worker URL」の「プロダクション」はオンにする（オフだと URL が開かず、検証も届かない）。「プレビュー」はオフでよい。
   - 確認：`/` に GET して、200 と `ok` が返ること。返らなければ、Cloudflare のデプロイの画面を見てもらう。
4. チャネルシークレットは、担当者が Cloudflare で自分で入力する（ボットは値を受け取らず、入力もしない）。次の内容をそのまま示す。
   - 開く画面：https://dash.cloudflare.com/?to=/:account/workers/services/view/:worker/production/settings （アカウントや Worker を選ぶ画面が出たら、自分のアカウントと `line-webhook-relay` を選ぶ）。うまく開かなければ https://dash.cloudflare.com/?to=/:account/workers-and-pages →「line-webhook-relay」→「設定」→「変数とシークレット」。
   - 入力のしかた：「追加」→ 種類は「シークレット」（暗号化される。「テキスト」は選ばない）→ 名前 → 値は LINE Developers でチャネルを開き、「チャネル基本設定」にあるチャネルシークレット（32文字）→「デプロイ」。
   - 入力する名前：1つ目のアカウントは `CHANNEL_SECRET`、2つ目からは `CHANNEL_SECRET_<名前>`（英数字と `_`。アカウントごとに変える。例 `CHANNEL_SECRET_SHOP`）。すでにある `CHANNEL_SECRET` は上書きしない（前のアカウントが 401 になる）。
   - 値はチャットに貼らない。入力が終わるまでメッセージは届かない。入力が終わったか聞き、最後は手順6の「検証」で確認する。
   - 別のアカウントのためにすでに中継を作ってある人は、手順1〜3を飛ばしてここだけ行う。
5. Webhook URL を、手順3の URL を使って組み立てて示す：`https://<Worker の URL>/webhook?url=〇〇&token=△△`
   - 〇〇：「LINE受信の記録」のサイドバーにある「Webhook URL」を URL エンコード（URL 用に変換）したもの。秘密ではないので、貼ってもらえば変換して返す。サイドバーからそのままコピーしてもらい、`https://api2.cursor.sh/` で始まることを確認する（打ち間違えると、お客様のメッセージと送信キーが別の宛先に渡ってしまう）。
   - △△：サイドバーの「Webhook key」にある送信キー。秘密なので、担当者が LINE Developers の入力欄で直接つなげる。完成した URL はチャットに貼らないよう伝える。
   - 複数のアカウントでも URL の形は同じ。2つ目のアカウントも同じ Worker の URL を使い、`url=`・`token=` はそのアカウント用のボットの「LINE受信の記録」のものにする。
6. LINE Developers で、そのアカウントのチャネルの「Messaging API設定」を開き（別のチャネルに貼ると 401 になる）、Webhook URL に手順5の URL を貼り、「Webhookの利用」をオンにして「検証」を押してもらう。成功したか聞き、失敗なら「うまくいかないとき」に進む。
7. 担当者のスマートフォンから LINE公式アカウントに1件送ってもらい、「LINE受信の記録」が記録したら完了（`DESK_DB=<保存先> python3 -I /workspace/line-inbox/bin/stats.py --days 1` で確認する）。最初に届いた Webhook の宛先が、このボットのアカウントとして登録される（`account.py show` で末尾4文字を確認できる）。
8. 送信用の接続（line-oa MCP）は、推測で説明せず、公式ページを示す。
   - https://developers.line.biz/ja/docs/messaging-api/getting-started/
   - https://developers.line.biz/ja/docs/basics/channel-access-token/
   - 設定する値は `CHANNEL_ACCESS_TOKEN`（line-oa が読む名前。担当者が秘密の値の入力欄に入れる）と `NPM_CONFIG_IGNORE_SCRIPTS=true`。
   - line-oa は1つの接続で1つのアカウントを扱う。このボットも1アカウント用なので、2つ目のアカウントにはボットをもう1つ作る。
   - スクリプト（`mark_read.py`・`quota_check.py`・`save_media.py`）は、同じチャネルアクセストークンを `LINE_CHANNEL_ACCESS_TOKEN` という名前で読む。読めなければ、秘密の値の入力欄で一度だけ入れてもらう。

## うまくいかないとき
- 401：シークレットが違う（チャネルアクセストークンや別のチャネル〈LINEログインなど〉の値を入れた、コピーで欠けた〈チャネルシークレットは32文字〉、発行し直した）。Webhook を設定したチャネルの「チャネル基本設定」からコピーし直し、Cloudflare で入れ替えてもらう（手順4の画面）。
  - 2つ目のアカウントのシークレットで `CHANNEL_SECRET` を上書きした（1つ目が 401 になる）。アカウントごとに別の名前で入れ直す。
  - `CHANNEL_SECRET_<名前>` の綴りが違う（`CHANNEL_SECRET-SHOP`、`CHANNEL_SECRETSHOP` などは読まれない）。
  - 中継が古いバージョンで、2つ目以降のシークレットを読まない。GitHub のフォークで「Sync fork」を押し、Cloudflare のデプロイが終わるのを待つ（設定は変えなくてよい）。
- 500：`CHANNEL_SECRET` も `CHANNEL_SECRET_<名前>` も1つも入っていない。
- 400：URL に `token=` がない。手順5の URL を組み立て直す。
- 403：`url=` が https でない、またはポート番号やユーザー名が入っている。サイドバーの Webhook URL をそのままコピーし直す。
- 別のアカウントのメッセージが届く（「別のアカウント宛てのメッセージが届きました」と出る）：そのチャネルの Webhook URL の `url=`・`token=` が別のボットのもの。そのアカウント用のボットのサイドバーから組み立て直す。登録したアカウントのほうが違っていたら、担当者に確認してから `account.py set --from-message <id> --relabel` を実行する（やり直すなら `account.py forget --yes`）。
- 何も届かない：「Webhookの利用」がオフになっている。ビルドが失敗する、URL が開かないときは手順2・3を見直す。
- 以前の名前（`grok-bot-line-relay` など）で中継を作っていて、「Sync fork」の後にビルドが失敗する：以前のバージョンは動き続けるので、慌てなくてよい。新しい名前 `line-webhook-relay` で Worker を作り（手順2）、シークレットを同じ名前・値で入れ（手順4）、LINE の Webhook URL を新しい Worker の URL に差し替えて「検証」し（手順5・6）、1件届くのを確認してから古い Worker を削除する。
- 設定を直した後、LINE Platform が以前のメッセージを再送することがあるが、記録は重複しない。
- 既読がつかない：故障ではない。応答設定の「チャット」がオンだと、届いただけでは既読にならない。

## 設定の後
- LINE公式アカウントのあいさつメッセージと、営業時間外の応答メッセージの文案を出す（ボットは送らない。例：「返信は営業時間内にいたします」「お急ぎの方はお電話でどうぞ」）。
- 伝える：「最初はすべて記録し、期限なく残します。記録しない項目や保存期間を決めたいときは言ってください。」
- 1つずつ聞く（どれも飛ばしてよい。飛ばしたら初期設定のまま）：業種 → 口調と署名 → お店・事業の情報 → 料金プランと月のメッセージ通数の上限 → NGワード → キーワード応答の自動送信 → 一斉配信の送り方。答えはメモリの「設定」「お店・事業の情報」に、選んだ値だけを書く（例：「一斉配信の送り方：担当者が管理画面から送る」）。
  - 料金プラン：分からなければ https://www.lycbiz.com/jp/service/line-official-account/plan を示し、管理画面でも確認できると伝える。プランの名前・料金・通数はボットから言わない。
  - キーワード応答の自動送信（オフ〈初期設定〉／オン。オンにすると、担当者が登録したキーワードと返事の組だけを、確認なしで送る）と、一斉配信の送り方（担当者が管理画面から送る〈初期設定〉／ボットから直接送る）は、何が起きるかと通数の使い方をメモリの「決まり」のとおりに伝えてから聞く。キーワード応答には「キーワードと返事は、このチャットで言っていただければ登録します。自動送信は、あなたが指示するまでオフのままです」と添える（登録は desk-keyword-reply スキル）。
  - 後から変える、初期設定に戻す場合も「決まり」に従う。
- 伝える：「決まった時間の報告はありません。『未返信は？』『週報を見せて』『残りの通数は？』と聞いてください。返信したいときは『〇〇さんに返信して』と言ってください。よく使う返事は『この返事を定型文にして』と言えば、次から使えます。届いた写真やファイルは自動で保存するので、見たいときは『見せて』と言ってください。」
- 最後に：
> 問い合わせが届いたら、ここでお知らせします。私が止まっていることもあるので、LINE公式アカウントアプリの通知はオンのままにしてください。
