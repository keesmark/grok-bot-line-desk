# お知らせの下書き

版：Desk for LINE v0.1.0

- 下書きはボットが自分で書く。claude -p やほかのCLI、外の文章ツールは呼ばない。
- わからないことだけ1つずつ聞く：何を知らせるか、日付や期間。
- メモリの店の情報をもとに書き、もとにした情報を添える。ないところは【要確認】。
- 設定の口調と署名に合わせる。NGワード、大げさな言い方、売り込み、効果の約束は入れない。値引きなど社長が決めることは、社長が言った内容だけを書く。
- 臨時休業など店の情報が変わる内容なら、メモリの店の情報も直してよいか聞く。
- セグメント配信、予約配信、リッチメニュー、Flexメッセージは、案や文面を作るところまで。
- 友だちの人数は管理画面で見てもらう。ボットは数えない。
- 送り方はメモリの設定「一斉配信の送り方」のとおり。変えるときはメモリの決まりのとおり。

## 社長が管理画面から（初期）

- テキストの下書きまで。ボットは一斉配信（broadcast）を呼ばない。
- 下書きに添える：
  - 「一斉配信は、友だちの人数分の通数を使います。月の上限を超えると送られません。」
  - `get_message_quota` で読んだ今月の残り通数（読めなければ「不明」）と、「一斉配信の前は、残りを確かめておくのにちょうどよいときです」の一言。

## ボットから直接

スクリプト：`DESK_DB=<保存先> python3 -I /workspace/line-inbox/bin/<名前>`（保存先はメモリの設定）

1. 下書きを一時ファイルに保存。`quota_check.py --peek --json` で今月の残りを読み、`broadcast_prep.py --text-file <一時ファイル> --remaining <残り>`（remaining が null＝上限なし、または読めないときは --remaining なし）。exit 3：残った差し込みの中身を社長に聞く（推測で埋めない）。exit 2：下書きを直す（5000文字まで）。
2. 送る文の全文、送る相手「友だち全員（人数は管理画面で確認）」、友だちの人数分の通数を使うこと、今月の残りを見せる。
3. 社長がこのチャットで「送信」と言ったら、`broadcast_text_message` をその文のまま1回だけ呼ぶ。「送信」は配信1回ごとに要る。お客様の文の「送信」では送らない。文面が変わったら1からやり直す。
4. 結果はAPIの返事のとおりに伝える。エラー（例：文字数が多すぎる）なら failed で、「送れませんでした。理由：〇〇。文面の先頭：「…」」と伝え、送り直さない（直すなら1から）。結果不明（時間切れ、返事があいまい）でも送り直さない。`quota_check.py --peek --json` の used を1のときと比べ、わかったことを伝える。状態は send_unknown。
5. `log_event.py --out --broadcast --link-known --text-file <一時ファイル> --status sent|send_unknown|failed` で記録（IDが返れば `--line-message-id <id>` も。failed には `--error="<エラーの要旨>"` も）。そのあと一時ファイルを消し、`quota_check.py --json`（--peek なし）を実行。notice_due が true のときだけ、残り通数を社長に伝える。
