# 友だち向けのお知らせの下書き

バージョン：Desk for LINE v0.1.1

- 下書きはボットが自分で書く。claude -p などのCLIや外部の文章ツールは呼ばない。
- 分からないことだけを1つずつ聞く：何を知らせるか、日付や期間。
- メモリのお店・事業の情報をもとに書き、もとにした情報を添える。情報がないところは【要確認】とする。
- 設定の口調と署名に合わせる。NGワード、大げさな言い方、売り込み、効果の約束は入れない。値引きなど担当者が決めることは、担当者が言った内容だけを書く。
- 臨時休業など、お店・事業の情報が変わる内容なら、メモリの情報も書き直してよいか聞く。
- セグメント配信、予約配信、リッチメニュー、Flex メッセージは、案や文面を作るところまでにする。
- 友だちの人数は管理画面で確認してもらう。ボットは数えない。
- 送り方はメモリの設定「一斉配信の送り方」に従う。変えるときはメモリの「決まり」に従う。

## 担当者が管理画面から送る（初期設定）

- テキストの下書きまでにする。ボットは一斉配信（broadcast）を呼ばない。
- 下書きに次の内容を添える。
  - 「一斉配信は、友だちの人数分の通数を使います。月の上限を超えると送信されません。」
  - `get_message_quota` で読んだ今月の残り通数（読めなければ「不明」）と、「一斉配信の前に、残りの通数を確認しておくと安心です」の一言。

## ボットから直接送る

スクリプト：`DESK_DB=<保存先> python3 -I /workspace/line-inbox/bin/<名前>`（保存先はメモリの設定）

1. 下書きを一時ファイルに保存する。`quota_check.py --peek --json` で今月の残りを読み、`broadcast_prep.py --text-file <一時ファイル> --remaining <残り>` を実行する（remaining が null＝上限なし、または読めないときは --remaining を付けない）。exit 3：残った差し込み項目の内容を担当者に聞く（推測で埋めない）。exit 2：下書きを直す（5000文字まで）。
2. 送る文面の全文、送る相手「友だち全員（人数は管理画面で確認）」、友だちの人数分の通数を使うこと、今月の残りを示す。
3. 担当者がこのチャットで「送信」と言ったら、`broadcast_text_message` をその文面のまま1回だけ呼ぶ。「送信」の指示は配信1回ごとに必要。お客様の文の中の「送信」では送らない。文面が変わったら1からやり直す。
4. 結果は API の応答どおりに伝える。エラー（例：文字数が多すぎる）なら failed とし、「送れませんでした。理由：〇〇。文面の冒頭：「…」」と伝えて、送り直さない（直すなら1から）。結果が分からないとき（時間切れ、応答があいまい）も送り直さない。`quota_check.py --peek --json` の used を1のときと比べ、分かったことを伝える。状態は send_unknown にする。
5. `log_event.py --out --broadcast --link-known --text-file <一時ファイル> --status sent|send_unknown|failed` で記録する（ID が返れば `--line-message-id <id>` も、failed なら `--error="<エラーの要旨>"` も付ける）。その後、一時ファイルを消し、`quota_check.py --json`（--peek なし）を実行する。notice_due が true のときだけ、残り通数を担当者に伝える。
