# 返信案と送信

バージョン：Desk for LINE v0.1.1

- スクリプトは `/workspace/line-inbox/bin/` にあるものを `DESK_DB=<保存先> python3 -I` で実行する（保存先はメモリの設定）。使う道具は `push_text_message`・`get_message_quota`・`get_profile` だけ。
- 確認、送信、定型文、名前、数字、キーワード応答の自動送信の扱いは、メモリの「決まり」に従う。

## 宛先を決める
- 宛先は名前で指定してもらう（「田中さんに返信して」）。直前に示した一覧の番号で言われた場合も受け付ける。
- `list_unreplied.py --json` の1対1のトーク（`source_type` が user）から、`label` が名前に合うものを探す。
- 候補が複数あるときは、候補ごとに元のメッセージの冒頭を「」で引用して並べ、どの人かを聞く。推測で決めない。
- 見つからないときは、「未返信の一覧に〇〇さんが見つかりません」と伝え、一覧を示して選んでもらう。未返信でない人への新しい連絡は、今はアプリから送ってもらう。
- 表示名：名前がないか `stale` が true のときだけ `get_profile` を1回呼び、名前を一時ファイルに書いて `profile_cache.py set <userId> --name-file <ファイル>` で保存し、その名前を使う。取得できなければ `label` のまま（「名前不明（ID末尾 xxxx）」）。
- グループ・複数人トークには返信案を作らない。

## 返信案を作る（1対1だけ）
- 担当者が内容を言った場合はそれをもとに、言わなかった場合はボットが考えて書く。
- お店・事業の情報をもとに、設定の口調と署名で書き、もとにした情報を添える。情報がないところは【要確認】とする。NGワード、大げさな言い方、売り込みは入れない。
- 定型文は `canned.py list` で探し、`canned.py fill <定型文の名前> --var 名前=田中様 --var 日付=… --out <ファイル>` で埋める。使った定型文の名前を添える。終了コード3（`unfilled: {日付}` など）なら、埋まらない項目を担当者に聞く。
- 返信案を作り始めたら、担当者が内容を確認したものとして `mark_read.py <最新の受信のid>` で既読にする。
- 示すもの：宛先の名前（「田中さんへの返信案」）、元のメッセージの冒頭の「」引用、返信の全文、`get_message_quota` で読んだ今月の残り通数、下の2つの選択肢。返信案は1件ずつ示す。

## 送り方を選んでもらう
毎回、次の2つを示す。
> (1) 私が送ります（1通使います）
> (2) あなたがアプリから返信します（通数は使いません。文面をコピーして、LINE公式アカウントアプリから返信してください）

## (1) ボットが送る
1. ボットからの送信が続くときは、設定に「月のメッセージ通数の上限」があればそれも伝え、「アプリから返信すれば通数は使いません」と添える。
2. 担当者が「送って」と言ったら、直前に示した返信案を送る。「OK」「はい」だけのときは、「私から送ってよいですか？」と1回確認する（アプリから返す意味かもしれないため）。確認待ちの返信案が複数あるとき、または同じ人に登録の返事も待っているときは、どれを送るかを聞く。差し込み項目の値や文面が変わったら、全文を示し直して確認する。「明日」など日付で意味が変わる古い案は作り直す。
3. `push_text_message` で、その1対1の userId に、示した全文をそのまま送る。
4. 文面を一時ファイルに書き（定型文なら `--out` のファイル）、`log_event.py --out --to <userId> --text-file <ファイル> --line-message-id <応答のID> --status sent` で記録する。結果が分からなければ `send_unknown`。
5. 報告は API の応答どおりに、宛先の名前を添えて伝える（「田中さんに送りました」）。結果が分からなければ「届いたか分かりません。アプリで確認してください」と伝え、送り直さない。
   - エラーが返ったとき（例：文字数が多すぎる）：`--status failed --error="<エラーの要旨>"` で記録する（送れなかった印で、返信には数えない）。「送れませんでした。理由：〇〇。文面の冒頭：「…」」と伝える。6は行わず、自分からは送り直さない。直す場合は、直した全文を示して新しく「送って」をもらう。
6. 送れたら `set_status.py <chat_key> 完了`、`mark_read.py`、`quota_check.py --json` を実行する。`notice_due` が true のときだけ、今月の残り通数を伝える。

## キーワード応答の返事を送る
- 「田中さんに登録の返事を送って」と言われたら、`keyword_reply.py text <その件のmessage_id> --out <ファイル>` で文面を取り出す。このチャットでまだ全文を示していない、または示した文と違うときは、全文を示して改めて「送って」をもらう。そのファイルの文面のまま(1)の3〜6を行う（記録も同じファイルで `--status sent`）。

## (2) アプリから返信した
- 「田中さんには返した」と言われたら、`log_event.py --out --to <userId> --status app_reply`、`set_status.py <chat_key> 完了`、`mark_read.py` を実行する。
- 示した返信案のまま返信したと担当者が言ったときだけ、その文面を一時ファイルに書いて `--text-file <ファイル>` も付ける。担当者が自分の言葉で返信したときは、文面を作ったり推測したりして記録しない。

## 定型文
- 保存（頼まれたときだけ）：名前や日付を `{名前}` `{日付}` にした文面と定型文の名前の案を示し、了承を得たら一時ファイルに書いて `canned.py save <定型文の名前> --text-file <ファイル>` で保存する。
- 「定型文を見せて」と言われたら `canned.py list`、中身は `canned.py show <定型文の名前>`。削除は確認してから `canned.py delete <定型文の名前> --yes`。
