# 返信案と送信

バージョン：Desk for LINE v0.1.1

- スクリプトは `/workspace/line-inbox/bin/` にあるものを `DESK_DB=<保存先> python3 -I` で実行する（保存先はメモリの設定）。使う道具は `push_text_message`・`get_message_quota`・`get_profile` だけ。
- 確認、送信、定型文、名前、数字、キーワード応答の自動送信の扱いは、メモリの「決まり」に従う。

## 宛先を決める
- 宛先は名前（呼び名でもよい）で指定してもらう（「田中さんに返信して」）。一覧の番号では選ばない（一覧を取り直すと順番が変わり、別の人を選ぶおそれがあるため）。番号で言われたら、「どなたへの返信ですか？名前で教えてください」と聞く。
- `list_unreplied.py --json --include-groups` を実行する。
- 先に、`name_stale` が true の人だけ（同じ人は1回だけ）`get_profile` を1回呼び、名前を一時ファイルに書いて `profile_cache.py set <user_id> --name-file <ファイル>` で保存する。そのあと一覧を取り直し、新しい `label` で探す。取得できなければ `label` のまま（「名前不明（ID末尾 xxxx）」）。
- 1対1（`source_type` が user）の件の中から、`label`（呼び名があれば呼び名）か `name`（LINEの名前）が、言われた名前と同じ件を探す（「さん」「様」の有無や全角・半角の違いは同じとみなす）。似ているだけの件は、合う件として扱わず候補として示す。合うのがグループ・複数人トークだけなら、「グループには返信案を作れません。アプリから返信してください」と伝えて終わる。
- 担当者の言葉に「ID末尾 xxxx」があれば、`short_id` が xxxx の件だけを探す（`name` には照らさない。LINEの名前に「ID末尾」を書いている人がいるため）。
- `name_clash` が true の件は、LINEの名前がほかの人の呼び名や LINE の名前と同じ（または「様」などを足しただけの）人で、`label` の後ろに「（ID末尾 xxxx）」が付いている。名前だけでは決めない。合うのがその件だけでも、ID末尾（`short_id`）と最後のメッセージの冒頭を「」で示し、「同じ名前の方がほかにもいます。この方ですか？」と確かめる。
- `like_nickname` が true の件は、LINEの名前がだれかの呼び名と同じ別の人。担当者はその呼び名の人のつもりで言っているので、名前が合っても選ばない。「〇〇という呼び名の方は、未返信の一覧にいません。LINEの名前が同じ別の方（『』）からのメッセージはあります」と最後のメッセージの冒頭を添えて伝え、その方に返信するかは担当者にはっきり選んでもらう。
- 候補が複数あるときは、推測で決めずに候補を並べる。各候補には、`label`（呼び名、または ID末尾付きの名前）、LINEの名前、ID末尾（`short_id`。label とは別に毎回書く）、最後のメッセージの冒頭の「」引用、待っている時間を書く。担当者には「どちらの方ですか？」と聞く。答えは、その候補の並びでの順番（「上の方」「2人目」）でも、メッセージの内容（「予約の方」）でもよい。答えは、いま示した候補に当てはめる（一覧は取り直さない）。
- 同じ名前の人で決まったら、「次から区別しやすいように、呼び名を付けますか？（例：田中（美容室））」と1回だけ聞く。付けるときは、ここで決めた人の `user_id` に付ける（名前で探し直さない）。
- 見つからないときは、「未返信の一覧に〇〇さんが見つかりません」と伝え、一覧を示して選んでもらう。未返信でない人への新しい連絡は、今はアプリから送ってもらう。
- 決めた件の `chat_key`、`user_id`、最新の受信の `id` を覚えておく（送る前の確認に使う）。

## 呼び名
- 呼び名は、このボットの中だけで使う名前。LINEの名前が同じ人や読みにくい人を区別するために、担当者が付ける。お客様には見えず、LINEの名前を取り直しても残る。
- 「田中さんの呼び名を『田中（美容室）』にして」「この方の呼び名を…にして」と言われたら、このチャットで直前に決めた人のことならその `user_id` を使う。直前のお知らせの人のことなら、`list_unreplied.py --json --include-groups` でお知らせと同じ ID末尾（`short_id`）の件を探し、その `user_id` を使う。そうでなければ `list_unreplied.py --json --include-groups` の中から「宛先を決める」と同じ方法で人を決める（グループで最後に書いた人にも付けられる）。一覧にいない人には、次にメッセージが届いたときに付けられることを伝える。
- 保存する前に、付ける相手の `label`、ID末尾（`short_id`）、最後のメッセージの冒頭の「」引用を示し、「この方に『田中（美容室）』と付けますか？」と確かめる。
- 了承を得たら、呼び名を一時ファイルに書いて `profile_cache.py nickname <user_id> --name-file <ファイル>` で保存する。以後は一覧、お知らせ、返信案の宛先で `label` に呼び名が出る。
- `already used for another person` と出たら、ほかの人の呼び名か LINE の名前と同じなので、別の呼び名を聞く。「名前不明」で始まるもの、「ID末尾」を含むもの、100文字を超えるもの、「様」などだけのものも付けられない（出た理由を伝えて、別の呼び名を聞く）。
- 消すときは `profile_cache.py nickname <user_id> --clear`。
- 呼び名にも、メモと同じく要配慮個人情報や人を評価する言葉を入れない。そういう呼び名を頼まれたら、別の言い方を提案する。
- LINEの名前のあとに「（ID末尾 xxxx）」が付いて出る人（`name_clash` が true）は、同じ名前の人がほかにもいる人。いつも「（ID末尾 xxxx）」を付けたまま示し、呼び名を付けるよう勧める。呼び名を付けると「（ID末尾 xxxx）」は消える。

## 返信案を作る（1対1だけ）
- お客様に送る文には呼び名を入れない。名前を入れるときは LINE の名前（`name`）を使い、なければ名前を入れずに書く。
- 担当者が内容を言った場合はそれをもとに、言わなかった場合はボットが考えて書く。
- お店・事業の情報をもとに、設定の口調と署名で書き、もとにした情報を添える。情報がないところは【要確認】とする。NGワード、大げさな言い方、売り込みは入れない。
- 定型文は `canned.py list` で探し、`canned.py fill <定型文の名前> --var 名前=田中様 --var 日付=… --out <ファイル>` で埋める（{名前} も LINE の名前で埋める）。使った定型文の名前を添える。終了コード3（`unfilled: {日付}` など）なら、埋まらない項目を担当者に聞く。
- 返信案を作り始めたら、担当者が内容を確認したものとして `mark_read.py <最新の受信のid>` で既読にする。
- 示すもの：宛先の名前と ID末尾（「田中さん（ID末尾 1a2b）への返信案」。呼び名があれば「田中（美容室）（LINEの名前：田中 花子、ID末尾 1a2b）への返信案」）、元のメッセージの冒頭の「」引用、返信の全文、`get_message_quota` で読んだ今月の残り通数、下の2つの選択肢。返信案は1件ずつ示す。

## 送り方を選んでもらう
毎回、次の2つを示す。
> (1) 私が送ります（1通使います。送るときは「送って」と言ってください）
> (2) あなたがアプリから返信します（通数は使いません。文面をコピーして、LINE公式アカウントアプリから返信してください）

## (1) ボットが送る
1. ボットからの送信が続くときは、設定に「月のメッセージ通数の上限」があればそれも伝え、「アプリから返信すれば通数は使いません」と添える。
2. 担当者が「送って」と言ったら、直前に示した返信案を送る。次のときは送らずに、全文を示し直して「〇〇さんに送りますか？」と聞く。
   - 返信案を示したメッセージのすぐ次の発言ではないとき（間にほかの返信案、お知らせ、一覧、受信のお知らせなどが入ったとき）。
   - 返信案を示してから日付が変わったとき。
   - 「OK」「はい」「1で」「(1)」だけのとき（アプリから返す意味かもしれないため、1回確認する）。
   - 「送って」に名前があり、返信案の宛先と違うとき。
   - 確認待ちの返信案が複数あるとき、または同じ人に登録の返事も待っているとき（どれを送るかを聞く）。
   - 差し込み項目の値や文面が変わったとき。「明日」など日付で意味が変わる古い案は作り直す。
   - 「返した」と言われた件や完了にした件の返信案は、もう送らない。
3. 送る直前に `list_unreplied.py --json --include-groups` を実行し、その `chat_key` の最新の受信の `id` が、覚えておいた `id` と同じか確認する。違えば（新しいメッセージが届いていれば）送らずに、新しいメッセージの冒頭を「」で示し、返信案のままでよいか、作り直すかを聞く。その件が一覧にないとき（返信済みや完了になったとき）も送らずに聞く。
4. `push_text_message` で、その1対1の userId に、示した全文をそのまま送る。
5. 文面を一時ファイルに書き（定型文なら `--out` のファイル）、`log_event.py --out --to <userId> --text-file <ファイル> --line-message-id <応答のID> --status sent` で記録する。結果が分からなければ `send_unknown`。
6. 報告は API の応答どおりに、宛先の名前を添えて伝える（「田中さんに送りました」）。結果が分からなければ「届いたか分かりません。アプリで確認してください」と伝え、送り直さない。
   - エラーが返ったとき（例：文字数が多すぎる）：`--status failed --error="<エラーの要旨>"` で記録する（送れなかった印で、返信には数えない）。「送れませんでした。理由：〇〇。文面の冒頭：「…」」と伝える。7は行わず、自分からは送り直さない。直す場合は、直した全文を示して新しく「送って」をもらう。
7. 送れたら `set_status.py <chat_key> 完了`、`mark_read.py`、`quota_check.py --json` を実行する。`notice_due` が true のときだけ、今月の残り通数を伝える。

## キーワード応答の返事を送る
- 「田中さんに登録の返事を送って」と言われたら、宛先は「宛先を決める」と同じ方法で決める。`keyword_reply.py pending --json` から、その `user_id` の項目を探し、その `message_id` で `keyword_reply.py text <message_id> --out <ファイル>` を実行して文面を取り出す（一覧の最新の受信の `id` は、キーワードの後に届いた別のメッセージのことがあるので使わない）。その人の項目がなければ「〇〇さんに送れる登録の返事はありません」と伝える。複数あれば、キーワードと文面の冒頭を並べてどれかを聞く。
- その `message_id` が一覧の最新の受信の `id` と違うときは、キーワードの後にもメッセージが届いている。後のメッセージの冒頭を「」で示し、登録の返事のままでよいかを先に聞く。
- 受信のお知らせや一覧で文面を見せていても、示したことには数えない。このチャットで、宛先の名前と ID末尾、文面の全文、今月の残り通数を示し、(1)の2と同じ決まりで「送って」をもらう。
- そのファイルの文面のまま(1)の3〜7を行う（記録も同じファイルで `--status sent`）。

## (2) アプリから返信した
- 「田中さんには返した」と言われたら、`log_event.py --out --to <userId> --status app_reply`、`set_status.py <chat_key> 完了`、`mark_read.py` を実行する。
- 示した返信案のまま返信したと担当者が言ったときだけ、その文面を一時ファイルに書いて `--text-file <ファイル>` も付ける。担当者が自分の言葉で返信したときは、文面を作ったり推測したりして記録しない。

## 定型文
- 保存（頼まれたときだけ）：名前や日付を `{名前}` `{日付}` にした文面と定型文の名前の案を示し、了承を得たら一時ファイルに書いて `canned.py save <定型文の名前> --text-file <ファイル>` で保存する。
- 「定型文を見せて」と言われたら `canned.py list`、中身は `canned.py show <定型文の名前>`。削除は確認してから `canned.py delete <定型文の名前> --yes`。
